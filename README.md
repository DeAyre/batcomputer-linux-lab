# 🦇 Batcomputer: Linux Server Lab

A hands-on Linux lab built lesson by lesson on an Ubuntu Server VM, themed after the Bat Family. Each lesson turns a Linux topic into something I build and run myself, and I document what broke and how I fixed it along the way.

I'm working toward a career in network engineering, so I'm using this lab to build real command-line, troubleshooting, and networking skills instead of just reading about them.

## Lab Environment

| Component | Details |
|-----------|---------|
| Host | Ubuntu PC running VMware Workstation |
| Guest | Ubuntu Server VM (`batcomputer`), NAT network |
| Client | MacBook, connecting to the VM over SSH |

## Whats in the Lab so Far
- **A Bat Family roster** of 8 users and a service account across 5 groups, created by a re-runnable script (`03-create-users.sh`)
- **Account controls:** a locked account, a 30-day account expiry, password aging, and a scoped sudo rule that lets one group run exactly one command
- **SSH key login** from my MacBook through the VMware port forward
- **A roster script** (`roster.sh`) that lists every user with their UID, lock status, and groups
- **A case-file system:** five case folders with evidence, generated by a single loop and a `printf` template
- **A log investigation pipeline:** `gen-log.sh` creates a fake access log, and `threat-report.sh` reports failed logins, top source IPs, and recent alerts
- **Backup and restore:** closed cases archived with `tar` and restored to a test folder to prove the backup works
- **Evidence protection:** hard links vs. symlinks, and immutable files with `chattr +i`


## Skills Demostrated
- User and group management (`useradd`, `usermod`, `groupadd`, `passwd`, `chage`)
- Least-privilege access with scoped sudo rules (`visudo`)
- Idempotent bash scripting with loops, `awk`, and `printf`
- Debugging scripts from error messages and `bash -n`
- Text-processing pipelines (`grep`, `awk`, `sort`, `uniq`, `sed`)
- Archiving and restoring with `tar`
- Hard links, symlinks, and inodes
- File attributes with `chattr` and `lsattr`
- Debugging silent errors (empty variables, whitespace mismatches)
